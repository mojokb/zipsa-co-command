# v0.0.5 release scope

This release packages the current locally maintained zipsa skills for Claude Code and Codex.
It supersedes the earlier v0.0.5 proposal on this branch. The old proposal remains available
in Git history; it must not be read as the behavior shipped by this release.

## Included

- Nine skills in each host distribution, adding grill, test and workflow to the six published skills.
- Fix/feature classification based on the existing contract, with reproduction and causal evidence before product-fix planning or edits.
- Questions separated into discoverable facts, authorized observations and user-owned decisions.
- Standalone build protection against unvalidated substantive design changes.
- Shared-premise investigation after two failed fixes.
- Requirement-linked plans, tasks, checks and review findings, with explicit unverified criteria.
- One-stage workflow checkpoints with approval preservation, evidence invalidation and interruption recovery.
- Offline HTML guidance, shared resources and a Python standard-library renderer.
- Conditional performance checks and bounded behavioral validation for future skill changes.
- A standard Claude plugin manifest, a separate Codex installation path and documented runtime requirements.

## Implementation roles

| Distribution | Lead and implementer | Read-only peer |
|---|---|---|
| Claude Code | Claude | Codex MCP |
| Codex | Codex | Claude CLI; independent Codex fallback for Claude account authorization 403 |

The earlier proposal made Codex generate code for Claude to apply. This release keeps the
already-used approach-review model instead. Both lead and peer form their own view before
comparison; the lead owns the final decision and writes authorized changes. No fixed retry
count authorizes another speculative fix.

## Deferred proposals

| Earlier proposal | Current disposition |
|---|---|
| HITL/AFK task labels | No new labels. Actual action-specific approvals and blockers control execution. |
| Mandatory vertical slicing | Dependency-ordered tasks and runnable acceptance checks remain; no universal slicing rule. |
| Mandatory CONTEXT.md/ADR sections | Existing repository instructions and relevant decisions are read; no new artifact convention imposed. |
| Separate spec-compliance review axis | Requirement/plan conformance is included in existing review evidence and findings. |
| `think --grill` mode | Requirements clarification has its own `zipsa-grill` skill. |
| Automatic phase or shipping loops | Excluded. Workflow stops after one stage; no implicit merge or deployment. |

These are dispositions of earlier ideas, not commitments for later version numbers.

## Verification boundary

Clean-install tests exercise both packaged resource trees and their offline renderer.
Native Claude manifest and marketplace validation check packaging without a model request.
The preceding local update used fresh Codex sessions for ten behavior categories across both
instruction variants. Native Claude model execution was blocked by account authorization
403, so that evidence is explicitly incomplete. Repackaging checks do not remove that limit.

See [installation](installation.md) and each host's `skill-validation.md` for verification and
upgrade procedures. Existing schema-version-1 checkpoints remain readable without a forced migration.
